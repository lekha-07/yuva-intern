# Logistics Data Analysis Internship Project

A 4-week data analytics internship project simulating an end-to-end data science workflow for a regional e-commerce logistics provider — from strategic planning through data preprocessing, exploratory analysis and visualization, to predictive modeling and optimization.

**Scenario:** A regional e-commerce logistics company operating 3 distribution centers (DCs) and last-mile delivery across 4 regions, facing challenges in route planning, inventory balancing, and on-time delivery performance.

## 🗓️ Week 1 — Strategic Planning and Data Exploration

**Report:** `Week1_Strategic_Planning_Logistics_Report.docx`
**Code:** `logistics_analysis_pipeline.py`

Defines the logistics scenario, identifies 4 KPIs (On-Time Delivery Rate, Inventory Turnover Ratio, Freight Cost per Unit Shipped, Order Fill Rate), and researches how regression, clustering, and optimization apply to route planning, demand forecasting, and inventory rebalancing. Lays out a 5-phase strategic roadmap (Data Collection → Cleaning → EDA → Predictive Modeling → Evaluation/Deployment) with illustrative Python snippets for each phase, including K-Means delivery-zone clustering, a Random Forest demand forecast, VRP routing pseudocode, and an inventory rebalancing rule.

**Run:**
```bash
pip install pandas numpy scikit-learn
python logistics_analysis_pipeline.py
```

## 🗓️ Week 2 — Data Collection, Cleaning, and Preprocessing

**Report:** `Week2_Data_Preprocessing_Report.docx`
**Code:** `data_preprocessing_pipeline.py`

Simulates a realistic order/inventory/delivery dataset (modeled on the Kaggle DataCo Smart Supply Chain dataset) with intentionally injected quality issues: missing GPS coordinates, duplicate orders, negative quantities, and extreme outlier distances. Documents and implements the correction techniques used:

- **Missing values:** drop rows missing structurally required fields (coordinates, delivery date); impute non-critical fields with median
- **Duplicates:** deduplicate on `order_id`
- **Outliers:** IQR method + domain-rule filters (e.g., quantity > 0, delivery date ≥ order date)
- **Inconsistent formatting:** text/date standardization
- **Scale differences:** Min-Max normalization for distance-based models like K-Means

**Run:**
```bash
pip install pandas numpy scikit-learn
python data_preprocessing_pipeline.py
```

## 🗓️ Week 3 — Advanced Data Analysis and Visualization

**Report:** `Week3_Advanced_Analysis_Visualization_Report.docx`
**Code:** `logistics_visualization_analysis.py`

Performs exploratory data analysis on a simulated, cleaned logistics dataset (~2,200 shipments) and produces 6 visualizations to surface trends, cost drivers, and bottlenecks:

| # | Chart | Purpose |
|---|-------|---------|
| 1 | Delivery time distribution (histogram + KDE) | Shows spread and central tendency of delivery times |
| 2 | Transportation cost by DC (boxplot) | Compares cost efficiency across distribution centers |
| 3 | Weekly shipment volume trend (line chart) | Reveals demand seasonality over time |
| 4 | Correlation heatmap | Quantifies relationships between distance, volume, cost, delay |
| 5 | Distance vs. cost (scatter + regression) | Visualizes the cost-distance relationship |
| 6 | Average delay by region (bar chart) | Flags regions most prone to late deliveries |

**Run:**
```bash
pip install pandas numpy matplotlib seaborn
python logistics_visualization_analysis.py
```
Outputs charts to `./charts/`, a dataset to `./logistics_dataset.csv`, and summary statistics to `./summary_stats.csv`.

## 🗓️ Week 4 — Predictive Modeling and Optimization

**Report:** `Week4_Predictive_Modeling_Optimization_Report.docx`
**Code:** `predictive_modeling_optimization.py`

Builds a delivery-time forecasting model and uses it to drive a downstream resource-allocation optimization.

**Modeling:**
- Compares 3 regression approaches — Linear Regression, Decision Tree, Random Forest — using RMSE, MAE, R², and 5-fold cross-validation
- Tunes the Random Forest via `GridSearchCV` (n_estimators, max_depth, min_samples_leaf)
- Evaluates the tuned model on held-out test data and reports feature importances

**Optimization:**
- Formulates a linear program (via `scipy.optimize.linprog`) to assign next-day regional shipment volumes to distribution centers, minimizing total model-predicted delivery hours subject to each DC's daily capacity
- Compares the optimized assignment against a naive fixed-assignment baseline and reports the improvement

**Charts produced:**
1. Predicted vs. actual delivery time
2. Residuals distribution
3. Feature importance (tuned Random Forest)
4. Model comparison (RMSE across models)
5. Optimized shipment assignment heatmap (Region → DC)

**Run:**
```bash
pip install pandas numpy scikit-learn scipy matplotlib seaborn
python predictive_modeling_optimization.py
```

## 📌 Project Flow

```
Week 1: Define scenario, KPIs, and roadmap
   ↓
Week 2: Simulate, clean, and preprocess raw logistics data
   ↓
Week 3: Explore and visualize cleaned data to surface insights
   ↓
Week 4: Forecast delivery times and optimize DC assignment based on the model
```

Each week's work builds directly on the previous one — the KPIs and data schema defined in Week 1 carry through preprocessing (Week 2), EDA (Week 3), and modeling/optimization (Week 4), so every result is traceable back to the original scenario and objectives.
